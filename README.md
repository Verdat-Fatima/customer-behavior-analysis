## 🔍 Overview

Retailers sit on a pile of transaction data and rarely use it to actually understand who's buying what, why, and how often. This project takes a raw customer shopping dataset through the full pipeline — cleaning in Pandas, storing it in PostgreSQL, answering business questions in SQL, and surfacing the results in a Power BI dashboard a non-technical stakeholder could actually use.

## 🗂 Dataset

The dataset contains **3,900 customer transactions** with 18 attributes covering demographics, purchase details, and shopping habits.

| Column | Description |
|---|---|
| `Customer ID` | Unique identifier for each customer |
| `Age`, `Gender`, `Location` | Customer demographics |
| `Item Purchased`, `Category` | What was bought |
| `Purchase Amount (USD)` | Transaction value |
| `Size`, `Color`, `Season` | Product attributes |
| `Review Rating` | Customer rating (1–5) |
| `Subscription Status` | Whether the customer is subscribed |
| `Shipping Type` | Standard, Express, Free Shipping, Next Day Air, etc. |
| `Discount Applied`, `Promo Code Used` | Discount usage |
| `Previous Purchases` | Purchase history count |
| `Payment Method` | How the customer paid |
| `Frequency of Purchases` | How often the customer shops |

## 🧹 Data Cleaning & Feature Engineering

Done in `customer_shopping_behaviour_analysis.ipynb`:

- Checked for nulls — missing `Review Rating` values were imputed with the **median rating per category**, not a global median, so ratings stay realistic within each product type.
- Standardized column names (lowercase, underscores) for cleaner SQL later.
- Found that `discount_applied` and `promo_code_used` were identical across every row, so `promo_code_used` was dropped as redundant.
- Engineered two new features:
  - **`age_group`** — customers split into `Young Adult`, `Adult`, `Middle-aged`, `Senior` using quartile-based binning (`pd.qcut`)
  - **`purchase_frequency_days`** — converted text frequency labels (e.g. `"Weekly"`, `"Fortnightly"`) into a numeric day count, making frequency usable in calculations instead of just being a category
- Loaded the cleaned dataframe into a PostgreSQL database using SQLAlchemy for the SQL analysis stage.

## 📊 Power BI Dashboard

Built in `Customer_Behavior_Dashboard.pbix`, the dashboard turns the SQL findings into a single interactive page:

- **KPI cards** — total number of customers, average purchase amount, average review rating
- **Donut chart** — customer split by subscription status
- **Clustered bar charts** — customer distribution and spend broken down by age group
- **Slicers** for `gender`, `category`, `shipping_type`, and `subscription_status`, so any of the visuals can be filtered on the fly

## ▶️ How to Run

1. Clone the repo and open `customer_shopping_behaviour_analysis.ipynb` in Jupyter.
2. Run the notebook top to bottom — it cleans the raw CSV and loads the result into PostgreSQL.
3. Update the database credentials in the notebook's SQLAlchemy connection cell to match your local Postgres setup.
4. Run the queries in `sql_analysis.sql` against the loaded `customer` table.
5. Open `Customer_Behavior_Dashboard.pbix` in Power BI Desktop and point it at the same table to explore the visuals.


A few notes on what I did, so you can adjust:

- I pulled the actual dashboard structure (KPI cards, donut chart, two clustered bar charts, four slicers) straight out of the `.pbix` file rather than guessing — that section should match what you built.

- The "Key Insights" section has placeholder bullets — swap them for your real numbers (e.g. actual revenue split by gender, actual top-rated products) once you've got the query outputs in front of you.
